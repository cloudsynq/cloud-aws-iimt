Theory Notes

Elastic Block Store — persistent hard drives for your EC2 instances. Complete beginner-friendly guide for 1st semester students.

1

What is Amazon EBS?

When you launch an EC2 instance, it needs storage — just like your laptop needs a hard drive. Amazon EBS (Elastic Block Store) provides that storage. It's a network-attached, persistent block storage volume that you attach to EC2 instances.


Persistent means the data survives even if the EC2 instance is stopped or restarted — just like your laptop's hard drive keeps your files even when you shut it down.

💿 Analogy — External Hard Drive

Think of EBS like an external USB hard drive.

You plug it into your laptop (EC2) and use it. If you shut down the laptop — the hard drive and its data are safe. You can unplug it and plug it into a different laptop (different EC2 instance). You can make a copy (snapshot) for backup.


The key difference: EBS volumes are attached over the network, not a physical cable. AWS handles all the hardware. You get fast, reliable storage without managing any disks.

🔗

Attached to EC2

One EBS volume is attached to one EC2 instance at a time (except io1/io2 Multi-Attach).

📍

Same Availability Zone

An EBS volume and the EC2 it attaches to must be in the same AZ. Mumbai AZ-a volume → Mumbai AZ-a instance only.

💾

Persistent Storage

Data survives stop/start of the EC2 instance. Only deleted when you explicitly delete it.

📏

Scalable Size

Start with any size. Increase size later without stopping the instance (no downtime).

2

EBS vs Instance Store

EC2 instances can have two types of storage. It's important to know the difference — choosing the wrong one means losing data.

FeatureEBS VolumeInstance Store
TypeNetwork-attached block storagePhysically attached to the host hardware
Persistence✅ Data persists on stop/restart❌ Data is LOST on stop, termination, or failure
Use forOS disk, databases, long-term dataTemporary caches, scratch space, buffers
Snapshot✅ Yes — backup to S3❌ No backup support
SpeedVery fast (gp3 up to 16,000 IOPS)Fastest (direct physical connection)
CostBilled per GB provisionedIncluded in instance price
Critical Rule
Never store important data on Instance Store. If the EC2 instance stops, the data is gone — permanently. Always use EBS for any data you need to keep.
3

EBS Volume Types

EBS comes in 6 types. They fall into two categories: SSD-backed (fast, for low-latency workloads) and HDD-backed (cheaper, for large sequential reads).


Key term: IOPS = Input/Output Operations Per Second. Higher IOPS = faster disk. Think of it like how many files your hard drive can read/write per second.

SSD-Backed (General Purpose & High Performance)

gp3 — General Purpose SSD

Best for: Most workloads

Size: 1 GB – 16 TB · IOPS: up to 16,000

Latest generation. Faster and cheaper than gp2. IOPS and throughput are independently configurable. Default choice for new volumes.

✅ Use for: OS volumes, web servers, dev/test
gp2 — General Purpose SSD (older)

Previous generation

Size: 1 GB – 16 TB · IOPS: 3 IOPS/GB, max 16,000

Older version of gp3. IOPS is tied to volume size (bigger size = more IOPS). Still works fine but gp3 is recommended for new volumes.

✅ Use for: Same as gp3, but prefer gp3
io2 — Provisioned IOPS SSD

Highest performance

Size: 4 GB – 64 TB · IOPS: up to 64,000

For mission-critical databases that need guaranteed, consistent, ultra-high performance. Expensive. io2 Block Express goes up to 256,000 IOPS.

✅ Use for: Oracle DB, SAP HANA, large MySQL
io1 — Provisioned IOPS SSD (older)

Previous high-performance

Size: 4 GB – 16 TB · IOPS: up to 64,000

Older version of io2. Supports Multi-Attach (same volume on up to 16 instances). Use io2 for new deployments.

✅ Use for: Critical DBs, Multi-Attach scenarios

HDD-Backed (Throughput & Cold Storage)

st1 — Throughput Optimized HDD

Large sequential reads

Size: 125 GB – 16 TB · Throughput: 500 MB/s

Good for big data, log processing, data warehouses. Cannot be a boot volume. Optimized for reading large files sequentially, not random access.

✅ Use for: Big data, Hadoop, log files
sc1 — Cold HDD

Cheapest EBS option

Size: 125 GB – 16 TB · Throughput: 250 MB/s

Lowest cost per GB. For infrequently accessed data. Cannot be a boot volume. Think of it as an archive drive.

✅ Use for: Archival, infrequently accessed files
Quick Decision Guide
New web server / OS volume? → gp3
High-performance database? → io2
Big data / log processing? → st1
Cheapest archival storage? → sc1
For all lab work? → gp2 or gp3 (free tier eligible up to 30 GB)

EBS Snapshots — Backup to S3

A Snapshot is a backup of your EBS volume saved to Amazon S3. You can use it to restore a volume, copy data to another region, or create a new volume from it.

📸 Analogy — Phone Backup

Snapshot = backup of your phone to Google Drive / iCloud.

Your phone (EC2 instance) keeps working normally. At any time you can take a backup (snapshot) of its storage (EBS) to the cloud (S3). If your phone breaks (instance crashes), you restore from the backup and get everything back. You can also restore the backup onto a different phone (different EC2 in a different region).

Incremental Snapshots

First snapshot = full backup. Every snapshot after = only the changes. Saves space and cost.

Cross-Region Copy

Copy a snapshot to any other AWS region. Used for disaster recovery — if one region fails, restore in another.

🖼️

Create AMI from Snapshot

Turn a snapshot into an AMI (OS image). Launch identical EC2 instances anywhere in the world.

🔄

Snapshot Recycle Bin

Accidentally deleted a snapshot? AWS keeps it in Recycle Bin for up to 365 days before permanent deletion.

5

EBS Encryption

EBS encryption protects your data at rest (stored on disk) and in transit (moving between EBS and EC2). It uses AES-256 encryption and AWS manages the keys automatically via AWS KMS.

What Gets Encrypted?Details
Data at rest on the volumeAll data written to the EBS volume is encrypted
Data in transitData moving between EC2 and EBS is encrypted
SnapshotsSnapshots of encrypted volumes are automatically encrypted
Volumes from encrypted snapshotsAny volume created from an encrypted snapshot is encrypted
Zero Performance Impact
EBS encryption has no measurable performance overhead — it runs transparently in the background. There is no reason NOT to encrypt. Always enable encryption, especially for volumes storing user data, passwords, or financial records.
6

Modifying Volumes — No Downtime

One of the most powerful EBS features: you can increase volume size, change volume type, or adjust IOPS while the instance is running. No restart needed.

📈

Increase Size

Expand from 20 GB to 100 GB while EC2 is running. Then extend the file system (using OS commands) to use the new space.

⚡

Change Type

Switch from gp2 to gp3 for better performance and lower cost — live, with no downtime.

🎚️

Adjust IOPS

Increase IOPS on io1/io2 volumes when your database needs more performance during peak load.

One-Way Rule — Can't Shrink!
You can increase an EBS volume size but you cannot decrease it. If you need a smaller volume, create a new smaller one and copy the data. Always plan your initial size carefully.
7

Attach, Detach, and Move Volumes

EBS volumes are like USB hard drives — you can plug them in (attach) and unplug them (detach) from EC2 instances, as long as they are in the same Availability Zone.

OperationRequirementNotes
AttachSame AZ as EC2Root volume attached at launch. Extra volumes can be attached anytime.
DetachVolume not in use (or unmounted)Safely detach data volumes. Root volume: must stop instance first.
Move to another AZTake snapshot → Create volume in new AZDirect move not possible — use snapshot as intermediary.
Move to another RegionCopy snapshot to new region → Create volumeSnapshot copy crosses regions, not volumes directly.
8

Root Volume vs Data Volume

🥾

Root Volume

The boot disk — contains the OS (Linux/Windows). Created automatically when you launch EC2. Deleted by default when instance is terminated (can be changed).

📁

Data Volume

Additional volumes you attach yourself. For storing app data, databases, files. Not deleted on termination by default. Can be detached and moved.

Protect Your Root Volume
By default, the root volume is deleted when an EC2 instance is terminated. To prevent accidental data loss, change the "Delete on Termination" setting to No when launching. This keeps the root volume even after termination.

Key Summary

  • 1
    EBS = network-attached persistent block storage for EC2. Like a USB hard drive that survives shutdowns.
  • 2
    Same AZ rule = EBS volume and EC2 must be in the same Availability Zone. To move across AZs, use snapshots.
  • 3
    Volume Types = gp3 (default, general purpose) · io2 (high-performance DBs) · st1 (big data) · sc1 (cheapest archive).
  • 4
    Snapshots = incremental backups stored in S3. Use them to backup, restore, copy across regions, or create AMIs.
  • 5
    Encryption = always enable it. AES-256, zero performance impact, managed by AWS KMS automatically.
  • 6
    Elastic Volumes = increase size, change type, or adjust IOPS without stopping the instance. Cannot shrink size.
  • 7
    Root vs Data volume = root has the OS (deleted on termination by default). Data volumes survive termination by default.
  • 8
    Instance Store ≠ EBS. Instance Store is faster but loses all data on stop/termination. Never store important data there.
