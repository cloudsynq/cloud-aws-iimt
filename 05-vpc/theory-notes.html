AWS VPC
Theory Notes

Virtual Private Cloud — your own isolated network inside AWS. Complete beginner-friendly guide for 1st semester students.

1

What is a VPC?

Before VPC existed, when you launched an EC2 instance it went directly on a shared public network — visible to the internet by default. As more companies moved to AWS, this became a serious security problem.


VPC (Virtual Private Cloud) solves this: it gives you a completely isolated section of the AWS cloud where you control the networking — your own IP address ranges, subnets, routing rules, and security.

🏢 Analogy — Office Building

Think of AWS as a huge commercial complex with thousands of offices.

Without VPC → you're working at a public co-working space. Anyone can walk up to your desk.


With VPC → you rent an entire private floor. Only your team gets access. You control which rooms have windows (internet access) and which are internal-only. You hire security guards and set up access control at every door.


VPC = your private floor in AWS's building. The building (AWS) manages power, cooling, and physical security. You manage everything inside your floor.

Key Facts
  • VPC is a regional resource — it spans all Availability Zones in a region
  • You can have up to 5 VPCs per region (default limit)
  • AWS creates a Default VPC in every region for you — great for learning, not for production
  • Resources inside a VPC are private by default — nothing is exposed unless you choose to expose it
2

IP Address Range (CIDR Block)

When you create a VPC, you give it a CIDR block — this is the range of private IP addresses your VPC can use. Think of it as deciding "how big is my office building?"

10.0.0.0 / 16 → VPC (65,536 IPs — the whole building)
10.0.1.0 / 24 → Public Subnet (256 IPs — public floor)
10.0.2.0 / 24 → Private Subnet (256 IPs — private floor)
Simple Rule to Remember
Smaller the number after / → bigger the range.
/16 = huge (65K IPs) · /24 = medium (256 IPs) · /32 = single IP

For practice: always use 10.0.0.0/16 for your VPC, then 10.0.X.0/24 for subnets.
3

VPC Core Components

🏗️

Subnet

A division of your VPC. Like a floor of your building. Each subnet lives in one Availability Zone.

🚪

Internet Gateway (IGW)

The main door connecting your VPC to the public internet. Without it, nothing gets in or out.

🗺️

Route Table

The directory/signage system. Tells traffic "if you want the internet, go through the IGW."

🛡️

Security Group

Firewall at the instance level. Like a security guard at each individual office room.

🚧

Network ACL (NACL)

Firewall at the subnet level. Like a checkpoint at the entrance to each floor.

📡

NAT Gateway

Lets private subnet servers reach out to the internet (to download updates) without being directly exposed.

4

Public Subnet vs Private Subnet

The most important concept in VPC architecture. The only difference between a public and private subnet is the route table — specifically, whether traffic can reach the Internet Gateway.

FeaturePublic SubnetPrivate Subnet
Route to Internet?✅ Yes (via IGW)❌ No direct route
Directly reachable from internet?Yes (with public IP)No
What goes here?Web servers, Load Balancers, Bastion HostDatabases, App servers, internal APIs
Example IP accessWorld can reach itOnly resources in the VPC
🏢 Building Analogy Continued

Floors with windows vs. interior rooms

Public Subnet = The ground floor reception and lobby. People from outside can walk in. Your web server (the receptionist) sits here — it talks to the public.


Private Subnet = The secure back office / server room. No windows. No direct external access. Your database (confidential files) stays here. Only internal staff (other servers inside the VPC) can access it.

For Beginners — Start With Security Groups
In most cases, Security Groups are enough. NACLs are an additional layer for extra security. Focus on Security Groups first — they handle 90% of real-world use cases.
6

Default VPC — What AWS Gives You

When your AWS account is created, AWS automatically sets up a Default VPC in every region. This is why you've been able to launch EC2 instances without manually setting up networking!

✅

Default VPC comes with:

CIDR: 172.31.0.0/16 · Internet Gateway attached · Public subnets in each AZ · Route table with internet route

⚠️

Why not use it in production?

All subnets are public. No private isolation. Good for learning, but a real application needs a custom VPC with proper separation.

Standard VPC Architecture (3-Tier)

In real applications, resources are separated into 3 layers — each with different security requirements. This is called 3-tier architecture.

Key Summary

  • 1
    VPC = Your own private, isolated network inside AWS. Full control over IP ranges, subnets, routing, and security.
  • 2
    CIDR Block = The IP address range for your VPC. Use 10.0.0.0/16 for practice (65,536 IPs).
  • 3
    Public Subnet = Has a route to the Internet Gateway → reachable from the internet. Put web servers here.
  • 4
    Private Subnet = No route to IGW → not directly reachable from internet. Put databases here.
  • 5
    Internet Gateway = The door between your VPC and the internet. Must be created and attached.
  • 6
    Route Table = Routing rules. Public subnets need a route "0.0.0.0/0 → IGW".
  • 7
    Security Group = Firewall per instance. Stateful — return traffic auto-allowed. Start here.
  • 8
    Default VPC = AWS created it for you. Fine for labs, but build a custom VPC for real apps.
